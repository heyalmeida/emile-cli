### Added
- **UI output commit frontier + viewport-budgeted prompt frame** (`specs/2026-10-10-ui-commit-frontier`, deep-dive P1-14 Stage A — subsumes P2-18 and P2-19): the duplication family (thinking § 7.2, large paste § 22.2, the partial "prompt cortado" frame) is now closed **by construction** instead of clamped. New `src/ui/commit-frontier.js` ports the reference pager's invariants with `file:line` citations — grok-build is Rust and ADR-0001 forbids a build step, so what is ported is the invariant, never literal code: a finalized block is written **once** with a trailing newline and never re-emitted (committing an id that is already committed is a no-op, `commit.rs:145-168`), a `write` that throws leaves the block **uncommitted** and the next frame retries it, and the module **only ever appends** — committed rows that overflow the live region (`stdout.rows - 1`) are released to the terminal's own scrollback (`liveRows()`/`releasedRows()`, `terminal.rs:661-687`, `:692-733`), never erased, with no cursor-up emitted at all. Multi-row commits are wrapped in DEC 2026 synchronized output (`ESC[?2026h`/`l`, `draw.rs:500-516`) and the wrapper is skipped when tmux is the immediate terminal (`$TMUX`, `tmux.rs:50-57`) or stdout is not a TTY. A **closed thinking block** (`printThinking` and the three `endThinkingStream` closes, keyed per stream so a double close cannot emit a second footer), a **finished tool grid** and a **completed assistant response** now go through the frontier as ONE write each instead of a row-by-row stream (which also charges the ADR-0003 lease one repaint instead of N); streaming content keeps its clamped paths until it closes. Separately, `buildPromptLayout` gains `maxRows` — the budget for the **whole assembled block**, because the builder is the only place that knows how many menu rows exist and whether a footer is present — and `promptFrameBudget()` feeds it `stdout.rows - 1` recomputed on every render; a draft that does not fit is windowed around the cursor row and the hidden rows are reported with the new dim visual vocabulary — `⌃ N earlier rows` above the window and `⌄ N later rows` below it, each omitted when its count is zero — the footer being sacrificed first and then the menu (windowed around the selection) on a very small terminal. **Invariant:** the drawn block never exceeds `stdout.rows - 1` rows, so the erase always reaches its own top and a stale frame is structurally impossible. `src/ui/terminal-cursor.js` stays the single clamp, and `clampedCursorUp` now reports `0` on a non-TTY stdout so an embedded escape is suppressed for exactly the same reason `writeCursorUp` suppresses its own. `test/commit-frontier.test.js` (15 tests) covers print-once, the failed-write retry (once), released overflow, `rows` honoured per commit, the never-erase rule and the wrapper/tmux/pipe matrix; `test/prompt-input-render.test.js` grows 20 → 31 with the budget window (marker counts, cursor always inside, `rows = 24` and `rows = 8`), the re-window while scrolling the caret, the submit-after-tall-draft remnant check and the P2-19 clamp assertions for `turn-keys`, `model-picker` and `prompt-input`.
- **Provider system: multi-slot credentials, `/provider` and custom endpoints** (`specs/2026-10-09-provider-system`, deep-dive P1-6 § 8.4): `~/.emile/config.json` becomes a version-2 document with one credential slot per provider (`providers{id: {apiKey, lastModel, …}}`), so switching providers no longer overwrites the previous key — connect once, switch with the new `/provider` command (masked listing, per-provider `lastModel` restore, session-stats context re-sync, never a mid-command password prompt; `/connect` on a configured provider offers Keep/Update/Remove). Legacy v1 files migrate on load. **Custom endpoints** register via `/connect` with three wire formats — Anthropic Messages (`/v1/messages`), OpenAI Chat Completions and OpenAI Responses (`store:false`) — implemented in `src/api/transports/` (new `base.js` shared retry/SSE/aggregation + `anthropic-messages.js` + `responses.js` fetch transports; `chat-completions.js` relocates the SDK path), all normalizing streamed events into the existing agent chunk shape (`agent.js` untouched). Security: credentials never follow a redirect (any `3xx` is fatal on the fetch transports), `http://` only for `localhost`/`127.0.0.1` enforced at write time **and** client-build time, keys masked to 4 chars everywhere and redacted in errors. Custom Chat Completions slots can name the reasoning-effort body key the server expects (`reasoningStyle`: `reasoning_effort`, `reasoning`, `thinking`, `enable_thinking`, `chat_template_kwargs`, `effort`, `reasoningEffort`, `both`, or catalog-auto). Reserved gateways keep byte-for-byte behavior; `test/provider-config.test.js` + `test/api-transports.test.js` (23 tests) cover the contract.
- **Dynamic memory mode and the `profile` type** (`specs/2026-09-04-dynamic-memory-mode`, ADR-0005): a sixth memory type `profile` covers personal context the user volunteers — name, personality, motivations, life situation, recurring personal rules. The model may now call `proposeMemory` proactively (without asking permission first) for that kind of fact, using `type: "profile"` or a `profile.*` / `personal.*` key. The `STABLE_EVIDENCE` source regex is bypassed only for the `profile` type; quoted-source, task-specific, credential/identifier/sensitive-topic/security-bypass denials, exact-source binding, two-session `auto` corroboration, conflict state, transient retrieval projection and full application-level deletion all remain authoritative. Retrieval weight for `profile` is 1.18 (between `user` 1.2 and `workflow` 1.15); MMR diversity, the 10 + 6 / 1 400-token budget and the existing `/memory`, `/remember`, `/forget` commands are unchanged.
- **Interactive pending-confirmation modal** (`specs/2026-09-04-memory-confirm-modal`, ADR-0006): when a turn produces one or more `pending` records, a `select`-based modal opens before the prompt re-attaches, offering `Aceitar` / `Recusar` / `Aceitar todas` per record. `Aceitar todas` is a single atomic mutation through the same lock + WAL + atomic-rename path as `/memory accept <id>`, and sets a per-process `skipConfirm` flag so the modal does not re-open for the rest of the session. The existing `/memory accept <id>`, `/memory reject <id>`, `/forget` and `/memory clear` commands remain the always-available escape hatch; new `/memory confirm-on` and `/memory confirm-off` re-enable or disable the modal mid-session. ### Fixed
- **No renderer can leave a stale prompt frame or ask for a climb the viewport cannot honour** (`specs/2026-10-10-ui-commit-frontier`, deep-dive P2-18 + P2-19, both closed by the P1-14 Stage A architecture): a draft taller than the terminal used to be drawn whole, so the clamped erase could not reach the block top and submitting left a **partial frame** in the scrollback — the "my prompt got cut" report of 2026-10-10 (the submitted text was never lost, only its rendering). The prompt block is now height-budgeted and windowed (see Added), so the erase is exact by construction. Three call sites still emitted an unbounded `ESC[nA` and are now routed through `src/ui/terminal-cursor.js`: `turn-keys.js` (the active-turn frame's row reservation, its caret climb and its hide climb — `clampedCursorUp`, embedded in the ONE write that frame is emitted as, the ADR-0003 lease rule), `prompt-input.js` (the legacy prompt's erase, leftover clear, caret climb and cleanup — embedded in the frame/erase write) and `model-picker.js` (its frame climb — `writeCursorUp`). On a non-TTY stdout no embedded climb survives either: `clampedCursorUp` reports `0` there, so a pipe, redirect or CI log receives no cursor-up escape at all. Nothing about the paste-burst coalescing (P0-4), the thinking append-only latch (P0-1), the turn-draft cap (P1-13) or the `shutdown()` handle (P1-15) changed, and the four UI suites kept their counts (all green).
- **A crash now runs the ordered shutdown instead of dying mid-way** (`specs/2026-10-10-crash-path-coordinator`, deep-dive P1-15 § 18): there was **no** `uncaughtException`/`unhandledRejection` handler anywhere in `src/` or `bin/`, so an error that escaped the agent's own try/catch killed the process through Node's default path — the session was never flushed to `complete`, global memory was not flushed, MCP child processes were left orphaned, the prompt's stdin lease was never released, and only the minimal ANSI reset ran. Both hooks are now installed and routed through the **same coordinator** the signals use (it already owns the exit and already maps a non-signal reason to code 1), so a crash takes the full 6-phase path exactly once. The line printed is **one redacted line on stderr** — `✗ Fatal (<origin>): <message>` — with `Bearer`, `api_key/token/secret/password`, `sk-…` shapes and control characters stripped and the text capped, because a provider error can carry the request body (the user's content): only a bounded description (`message`, plus `code`/`status`) is ever printed, never the raw error object. The handler cannot throw — a coordinator that fails, a rejecting coordinator promise or a broken stderr all fall back to a last-resort ANSI reset + `exit(1)`. Separately, `bin/emile.js` called `console.clear()` **before** printing its fatal error, so a crash wiped the scrollback the user was reading *and* the evidence of the bug; the bootstrap catch now goes through the same fatal path without clearing the screen (the `console.clear()` in `/switch` is a deliberate mid-session redraw and stays). `test/lifecycle-crash.test.js` (12 tests) covers the coordinator-once/exit-1 contract for both hooks, the redaction sentinels, non-Error reasons (string, plain object, `null`, `undefined`, exotic values), the throwing/rejecting coordinator fallbacks, the bootstrap path and the source assertions. **Behaviour note:** installing these handlers disables Node's default dump-and-exit — that is deliberate, and the handler always ends the process rather than resuming the REPL.
- **The recovery and shutdown surface tells the truth** (`specs/2026-10-10-lifecycle-recovery-integrity`, deep-dive P0-3 § 10/§ 18, with **P2-12 folded in**): six defects shared one boundary — where emile crashes, aborts or exits. (1) The boot scan and `listPending()` filtered a status `'pending'` that **no writer ever produces** (`saveSession` writes `tool_pending`/`complete`), so the feature that exists to surface a mid-tool crash reported 0/0 forever; it now selects `tool_pending`, and the dead export is renamed `listToolPending()`. (2) Corrupt records were counted but never moved, so they came back on every boot; the scan now **quarantines** them into `.emile/history/corrupt/<id>/` (its only write — it still executes nothing and rewrites no record) and reports what it moved. (3) The boot report read `recoveryReport.abandoned`, a field that never existed; it now prints the real counts, only when there is something to say, with the next step spelled out. (4) `markAborted` was dead code that would have **destroyed resumability** if wired (it overwrote `status: 'aborted'`, erasing the `tool_pending` marker and `pendingToolCalls`); it is now additive — it records `aborted`/`abortReason` and never touches `status` or the pending batch, so an interrupted turn still replays. (5) Idle SIGINT left the terminal broken: `stop-input` called a hook that was hard-wired to a **no-op**, so the prompt's keypress listener stayed attached and raw mode was never restored; the coordinator now takes the live prompt's real teardown (exposed on its `onReady` handle — the same path its own Ctrl+C uses), and the REPL returns immediately when the coordinator owns the exit. (6) Every exit **wiped the transcript** (`\x1B[2J`+`\x1B[H` in `restore-terminal`, plus `console.clear()` on the normal exit path) and a **second Ctrl+C did nothing** — the header promised a force-exit that the guard never performed. The screen is never cleared now, and a second signal exits synchronously with the same code (SIGINT→130, SIGTERM→143). Finally, session writes are **atomic** (temp file → `fsync` → rename, with cleanup), so a forced exit can no longer truncate the JSON and manufacture the very corruption the recovery layer reports, and `flushSync()` is a real durability step instead of a documented no-op. Tests: `lifecycle-recovery` (6), `lifecycle-stdin` (3), `session-atomicity` (5), `session-abort` (5); mutation-verified — reverting the status filter, the quarantine, the additive abort, the atomic write, the force-exit, the screen fix or the teardown injection each makes the new suites fail.
- **Input typed during a running turn is no longer silently truncated** (`specs/2026-10-10-turn-input-cap`, deep-dive P1-13 § 19): while a turn ran, keystrokes went to `listenTurnKeys`, whose draft was hard-capped at **400 characters** with the excess discarded without a word — the insert path stopped accepting keys once full and the same gate covered `Enter` inside a paste, so an 8 KB paste kept its first 400 characters and lost every line after them (reported 2026-10-10 while dispatching a brief by paste). `sanitizeLine` also collapsed whitespace runs and stripped tabs, corrupting pasted code, and the 90-char queue preview implied the whole text was taken. Now: the draft is bounded at a documented **`TURN_INPUT_MAX_CHARS = 16_000`** (a memory guard, not a UX limit — the idle prompt accepts input of any length), the **oldest** characters are dropped when the cap is reached so the newest text always survives, ONE dim notice per turn says `⚠ queued draft reached 16k chars — oldest text dropped`, the footer shows `queued draft: 12.8k/16k` once the draft passes 80% of the cap, the preview appends `… (+N chars)` when it truncates, and `sanitizeLine` no longer rewrites content — it only normalizes CRLF and replaces control characters, keeping tabs and internal spacing byte-identical (a whitespace-only draft is still not queued, decided at the submit site). `test/turn-input-cap.test.js` (14 tests) covers the 20 000-char drop-oldest case with its single notice, head-trimming on a second paste, tab/spacing integrity, control-character safety, the footer counter, the preview marker, pasted newlines landing past the old cap and the idle-prompt no-regression check. **Behaviour change:** the active-turn draft limit moves from 400 to 16 000 characters and reports itself.
- **The live thinking stream renders each fragment exactly once** (`specs/2026-10-10-thinking-append-only`, deep-dive P0-1 § 7.2 — the flagship defect of the duplication family): `appendThinkingStream()` repainted the **whole** accumulated reasoning block on every delta and climbed back to its top with an **unclamped** `ESC[nA`. That is correct only while the block still fits above the cursor: once it exceeded `stdout.rows` the cursor-up stopped at the viewport top, the older frames had already scrolled out of reach, and every later delta painted the block again below the previous one — the same thought appearing N times, which users read as the agent hallucinating. On a non-TTY stdout (pipe, `tee`, redirect) cursor movement is ignored entirely, so *every* cumulative frame landed in the output. The stream now has two strategies: it **redraws in place** only while the block fits and stdout is a TTY (its climb goes through the shared viewport clamp), and otherwise latches **append-only** for the rest of that stream — emitting just the lines not yet printed, keeping the newest line as an open tail that is rewritten in place only when its text actually changes, and never erasing anything that may have scrolled. `endThinkingStream()` closes the tail and appends a fresh `✻ Thought for Ns` footer instead of climbing to a possibly scrolled header. Collapsed mode, the wrap math and the `EMILE_DEBUG_THINKING` diagnostics are unchanged, and the public API is identical. The viewport clamp itself moved to a new shared module, `src/ui/terminal-cursor.js` (`viewportCursorUp`/`writeCursorUp`/`clampedCursorUp`), which the persistent prompt now imports — a verbatim move, proven by the unchanged 20 render tests. `test/thinking-stream-append.test.js` (9 tests) counts marker occurrences across the raw writes instead of comparing the final buffer (deep-dive § 7.3 explains why that method never caught it): a non-TTY 210-line stream emits the marker exactly once with **no** cursor-up at all, a `rows=24` TTY emits it once with a max climb of 9 (never above `rows-1`), a fitting stream still redraws in place, and the collapsed output is byte-stable.
- **A dead stream no longer poisons a session** (`specs/2026-10-09-assistant-null-poison`, deep-dive P0-6 § 10): a stream error or an empty response used to push `{role:'assistant', content:null}` into the live history, and the persistence projection strips `reasoning_content`, so exactly that record landed on disk. Every later request resends the whole history and the provider answers `400 messages[i] needs content or tool_calls` — not retryable and not a context overflow, so compression never triggers: the session was permanently dead and each new "Prossiga" appended another poisoned record. One exported predicate (`isValidAssistantMessage` in `history.js`) now guards all three boundaries: the loop never pushes an assistant with neither content nor tool_calls (error/reasoning-only turns contribute nothing to the model), `preparePersistedMessages` drops it before the write, and `getSessionRecord` filters it on read — so **existing corrupted sessions self-heal when resumed**, without any file being rewritten in place. `content:null` **with** `tool_calls` stays valid everywhere (it is the shape providers themselves return for a tool-only turn), consecutive `user` messages left by load filtering are kept as-is, and the cancel path keeps its semantics (partial text kept, incomplete tool calls discarded). The dead `streamErrored` flag is now set, so a zero-chunk stream error no longer prints both "Stream error" and "· (empty response)". `test/history-sanitize.test.js` (17 tests) covers the predicate matrix, both boundaries, the user's reported `assistant null / user "Prossiga" ×3` file, and a provider emulation that rejects the invalid shape — each guard was mutation-verified to fail its test when reverted.
- **Tool-executed subprocesses no longer inherit provider credentials** (`specs/2026-10-09-subprocess-env-scrub`, deep-dive P0-5 § 22.3): `runCommand` called `exec()` with no `env` option, so every command the model or the user ran — including an `npm install` postinstall script or a fetched `curl | sh` payload — inherited the **whole** environment: `OPENROUTER_API_KEY`, `REQUESTY_API_KEY`, `OPENCODE_API_KEY` and any other secret exported in the launching shell. A new `buildScrubbedEnv(baseEnv)` in `src/tools/security.js` (the module that already owns the command whitelist and `resolveSafePath`) returns a copy with every secret-shaped and injection-prone name deleted — case-insensitive on the **name** because Windows env names are case-insensitive — matching `KEY|SECRET|TOKEN|PASSWORD|PASSWD|CREDENTIAL`, `*_PAT`/`PAT`, `LD_PRELOAD`, `LD_LIBRARY_PATH`, `DYLD_*` and all `EMILE_*`. Policy is **deny-by-pattern, never allow-by-list** (an allowlist would break arbitrary builds: `PATHEXT`, `SystemRoot`, `COMSPEC`, `TEMP`, `JAVA_HOME`, … all survive), the emile process keeps its own environment (`config.js` resolution untouched, the parent object is never mutated), and **no flag, config or env var can disable it**. `isSafeCommand`, the metacharacter gate, safe-mode confirmation and dry-run are unchanged; the cwd probe still works because it sets `EMILE_COMMAND_STATUS` inside the child shell. `test/subprocess-env-scrub.test.js` (7 tests) covers the unit matrix, case-insensitivity, non-mutation, loader variables and a **real subprocess dumping its own environment** through the actual handler (mutation-verified: the test fails with the fix reverted).
- **Large paste no longer duplicates itself in the persistent prompt** (`specs/2026-10-09-paste-burst-redraw`, deep-dive P0-4 § 22.2): pasting a big prompt used to repaint the whole block on **every character and every pasted Enter** (2 KB ≈ 2 000 redraws) and erase it with an uncapped `ESC[nA`; once the block exceeded `stdout.rows` the cursor-up clamped at the viewport top, older frames had already scrolled out of reach, and each new line repainted the block below the previous one — the pasted text appeared N times. Now (a) a bracketed paste performs **zero** renders inside the burst and exactly **one** on `paste-end`, (b) terminals without bracketed paste are covered by burst coalescing — ≥3 text keypresses arriving within 2 ms are treated as one paste, flushed by a 10 ms quiet timer or by the first non-text key, so the screen always matches the draft before an editing key acts, and (c) **every** cursor-up is clamped to `Math.min(n, (stdout.rows || 24) - 1)` and skipped entirely on a non-TTY stdout: height overflow degrades to scrolling, never to duplication. Enter outside a paste still submits (a coalesced burst can never swallow it) and pasted Enters still insert newlines. Public API (`persistentPromptInput`, `buildPromptLayout`, `clipLine`, `matchPromptCommands`) and the width guarantee are unchanged. `test/prompt-input-render.test.js` gains 7 render cases (13 → 20): bracketed 500-char/20-line paste ≤2 renders, 200-key burst <10 renders, `rows = 10` + 30-line draft never emits `ESC[nA` above 9, non-TTY emits no cursor-up, and no write lands after cleanup.

  - Supported filenames that resolve outside the workspace through a symlink are rejected; ANSI/OSC/DCS controls are stripped before `/rules` renders file content.

### Fixed
- **Premature context compression** (`specs/2026-08-25-context-aware-compression`): the history gate now uses 80% of the active model's real token window from the shared model catalog instead of fixed 40k/120k raw-character limits. A 50k-token session on a 1,048,576-token model no longer compresses early; full-payload estimates include compressed secondary system messages, and post-compression hysteresis requires more than 40% history growth before another attempt.
- **Agent-loop crash after a response:** the module split left `calculateCost` out of `agent/agent.js` imports, causing `ReferenceError: calculateCost is not defined` when API usage arrived; the import is restored. The CLI's stale `./tools.js` import now points to the `tools/` barrel as intended.
- **Prompt multiline corruption** (`specs/2026-08-25-prompt-multiline-fix`, pass 4 of the TUI overhaul):
  - When the input wrapped past the terminal width, the screen filled with duplicated/garbage rows and deletions looked like no-ops. Root cause: the writing field was written as a single string and left to terminal auto-wrap (invisible to the redraw's row count), plus a cursor column that could overflow past the line end.
  - Fix: the field now draws one explicit erase-and-write per wrapped row (terminal never auto-wraps), continuation rows indent under the prompt glyph, and the cursor column is computed from the rendered rows and clamped within it. Verified with a virtual-terminal ANSI simulator (typing 200 chars + deleting all leaves exactly one clean prompt row).
- **Open boxes — side borders removed, top-border color fixed** (`specs/2026-08-25-tui-open-boxes`, pass 3 of the TUI overhaul):
  - All boxes (response, config, help, diff, startup header) now render with **top and bottom borders only** — no left/right `│` rails. This eliminates the chronically misaligned right border, whose padding was computed from `stripAnsi().length` (not the real display width for wide/emoji characters).
  - The response box's **white top border** is fixed: the `emile` label's ANSI RESET was nested inside a `C.muted(...)` wrapper, killing the muted color for the dashes after it — border parts are now composed separately.
  - Box content indents 4 spaces under the top border; diff rows keep line numbers and add/remove colors with truncation; the markdown code rail aligns with the new indent.

### Added
- **Dynamic model catalog via OpenRouter** (`specs/2026-08-25-dynamic-model-catalog`):
  - `initModelCatalog()` fetches the public unauthenticated OpenRouter catalog (417 models at time of writing) once per startup — context window, USD pricing and reasoning capability now come from live data instead of the static table.
  - Resolution cascade: dynamic exact-id → dynamic last-segment match (bare ids like `glm-4.6` resolve against prefixed catalog ids) → static table → safe default.
  - Offline resilience: the catalog persists to `.emile/models-cache.json` (gitignored); a failed fetch falls back to the persisted cache (up to 30 days), then to the static table — never blocks or crashes startup.
